# ADR-0006 · 独立替换桌面采样与用户状态估计

Accepted · 2026-11-10 · 负责人 A，联调方 B、C、D

原 live 读取路径在查询 OS 的同时给出状态。回放直接指定 working 或 available，因此即使软提醒在预期时间显示，也无法从该结果确认是哪条实际信号触发了估计。

1. A 定义两个可独立装配的进程内端口。采样器传出带 ID、来源、时间和能力标记的 RawSignals；估计器只接收该样本，传出可追溯证据的 UserStateEstimate。平台 API 集中在采样器，场景可直接输入同一结构。
2. 观察管线按注入时钟判断样本和估计有效期，保存基础估计，并将有期限的用户纠正应用到当前 Observation。read/pump 刷新观察，GUI 用缓存的 ObservationFrame 展示同轮结果。纠正记录 origin，回放、自动操作与人工输入可分别核验。B 继续使用原观察读取端口。
3. 原生 Qt 主线程采样后跨线程发送原始样本，服务线程更新管线并驱动任务。轮询已有值只重算其有效性。采样噪声不递增上下文版本，迟到决定仍以语义版本及有效期校验。
4. 历史 v1 场景可继续直接指定状态以复现调度用例。估计器验收以带时间的原始样本和证据引用为输入输出，真实桌面采样另须显式运行 live-smoke 并保留平台证据。

本决策固定观察边界。未来模型估计器可用相同样本与规则基线对照。System 2 的实际模型调用、策略路由和效果仍需另外实现和验收。
